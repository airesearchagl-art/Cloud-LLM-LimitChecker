# Codex Usage 手動スナップショット（opt-in）

Codex CLI（確認時点のバージョン）には、契約上のCodex利用枠（5時間枠・週次枠）を機械可読に取得できる公式のCLIフラグ・hook・APIが存在しません。公式に確認できるのは、Codex CLIの`/status`または公式Usage画面での対話表示のみです。

この機能は、その`/status`または公式Usage画面でユーザー自身が確認した値を、このアプリへ**手動で入力**して保存する仕組みです。Codexの自動実行、`/status`のスクレイピング、内部JSON-RPC、非公開APIはいずれも使用しません。

## 使い方

1. Codexで`/status`を開く（またはブラウザで公式Usage画面を開く）
2. 5時間枠・週次枠それぞれの残り%とreset日時を確認する
3. 通常管理画面（`/`）の「Codex Usage（手動入力）」セクションへ、確認した値を手入力して保存する
4. `/compact`で反映を確認する（5時間枠・週次枠のカードが更新され、「手動確認値」バッジと最終手動確認時刻が表示される）

5時間枠・週次枠は片方だけの入力でも保存できます。両方未入力のまま保存することはできません。

## 自動取得ではないことについて

- このアプリがCodexを起動したり、`/status`画面を読み取ったりすることはありません。
- 保存されるのは、あなたが入力した時点の値のスナップショットです。Codexの利用が進んでも、再度手入力するまで値は変わりません（`/compact`では「最終手動確認値」であることが明示されます）。
- reset時刻を過ぎても新しい手入力がない場合は、古い値を現在値のように見せず、「reset時刻超過」として扱います。

## 内部JSON-RPCやスクレイピングを使わない理由

- Codex CLIの内部JSON-RPC（`app-server`等）や未文書化のエンドポイントは、将来のバージョンで変更・削除される可能性があり、認証情報やセッション情報に触れるリスクもあります。
- `/status`画面や公式Usage画面の自動スクレイピング・OCRは、表示形式の変更に弱く、意図しない情報（他のセッション内容等）まで取得してしまうリスクがあります。
- 公式に保証された機械可読経路が存在しない現状では、ユーザー自身が公式画面で確認した値を手入力する方式が、最も安全で壊れにくい選択です。

## 保存先

Windows環境では以下に保存されます（このリポジトリの外、Claude Code Usageのキャッシュファイルとも別ファイルです）。

```text
%LOCALAPPDATA%\Cloud-LLM-LimitChecker\codex-usage.json
```

書き込みは一時ファイルへ書いてから原子的に置換するため、読み取り側が壊れた/半端なJSONを見ることはありません。

## 保存されるフィールド

- `schema_version` / `source`（固定値 `codex_manual`）
- `observed_at`（保存時のUTC時刻）
- `five_hour` / `weekly`（それぞれ`used_percentage` / `remaining_percentage` / `resets_at`）

Codexのセッション情報、transcript、prompt、model、context window、token数、認証情報、`/status`全文、Usage画面のHTML、stdout/stderrはいずれも保存しません。credits（クレジット残高）も、公式表示から安全に確認できる構造がまだ固まっていないため、Phase 1の対象外です。
